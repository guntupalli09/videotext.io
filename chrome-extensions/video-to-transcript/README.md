# Video to Transcript — VideoText (Chrome extension)

A Chrome MV3 extension that lets a signed-in VideoText user upload an audio or video file and get a
transcript back. It is a **client** for the existing VideoText product — it adds no transcription
backend, no second account system, and no new API.

> Architecture audit and integration design:
> [`docs/chrome-extension-video-to-transcript-audit.md`](../../docs/chrome-extension-video-to-transcript-audit.md)

## Layout

```
manifest.json           MV3 manifest (permissions: storage + api.videotext.io)
src/
  popup.ts              UI state machine: idle → uploading → processing → result/error
  content-auth.ts       content script, https://videotext.io/extension-auth ONLY
  lib/
    config.ts           production origins, tool type, polling/chunking constants
    api.ts              VideoText API client (upload, job status, usage, transcript)
    session.ts          chrome.storage.local: session token + in-flight job
    validation.ts       advisory pre-flight (type, size, duration)
    transcript.ts       segments → text, download filename
    languages.ts        the production language list
    errors.ts           API/network error model
public/                 popup.html, popup.css
icons/                  16/32/48/128, downscaled from client/public/icons/icon-192.png
scripts/                build, zip, icon generation, bundle security audit
tests/                  node:test suites (manifest, bundle/ZIP, client behaviour)
store/                  Web Store listing copy and submission checklist
```

## Commands

From the repository root:

```bash
npm run chrome:transcript:build   # type-check, compile, package, audit
npm run chrome:transcript:test    # 44 tests
```

Or from this directory: `npm run build`, `npm test`, `npm run typecheck`, `npm run audit`,
`npm run icons`.

Output: `dist/` (load unpacked) and `artifacts/videotext-video-to-transcript-v1.0.0.zip`
(Web Store upload, `manifest.json` at the archive root).

## Design decisions worth knowing

* **No bundler, no minifier.** `tsc` emits plain ES modules; `dist/*.js` is readable. A Web Store
  reviewer can verify "no remote code, no eval" by reading the package.
* **No background service worker.** Nothing needs to run while the popup is closed: an in-flight job
  lives on the VideoText backend, and the popup resumes polling it on reopen from
  `chrome.storage.local`. This keeps the permission set to `storage` alone.
* **No analytics.** The web app's PostHog/Sentry/Vercel instrumentation is deliberately not carried
  into the extension.
* **Server is the source of truth.** The extension does no entitlement arithmetic. Plan limits come
  from `GET /api/usage/current` at runtime; quota, rate-limit, size, duration and subscription checks
  all happen in `runTranscriptionIntake()` before a job exists. Backend refusals are rendered with
  the server's own message.
* **Progress is never invented.** Percentages come from chunks the server accepted or from the
  worker's own `progress`; the queue line comes from `queuePosition`. A single-request upload shows
  an indeterminate state rather than a fake bar.

## Backend touchpoints

Two additive changes in this repository support the extension:

* `server/src/utils/allowedOrigins.ts` — `EXTENSION_ORIGINS` allows explicitly listed
  `chrome-extension://<id>` origins through CORS. Unset by default, so nothing changes until it is
  configured. (`isAllowedRedirectOrigin()` keeps those origins out of the Stripe redirect allowlist.)
* `client/src/pages/ExtensionAuth.tsx` + the `/extension-auth` route — hands the user's existing
  session token to the extension after they sign in normally.
